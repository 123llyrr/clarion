# Catalina 证据复核与合成器底层重构（2026-10-11）

本轮完成帧预算恢复、共享损伤区域算法、SHM 上传、窗口成员查找和 Dwindle 递归存储的改进。目标是减少可以定位的额外工作与崩溃风险。当前证据包含 macOS 静态反编译、本项目回归、CPU 微基准和双显卡像素/同步验证；尚无相同负载的 Catalina 桌面对照，也没有新版本真实桌面的前后帧时间对比。

## 静态逆向依据及边界

使用已恢复的 Catalina BaseSystem `SkyLight` 样本，大小 4,193,888 字节，SHA-256 为 `38cde43140bfb76a9cc19cda64fc8e8d260c8c25963bfba650a3f078d8d5b78b`。REA/Ghidra 取得五个完整函数体，合计 914 字节与原始样本逐字节一致，16 条 canonical evidence 经实际导入验证。样本未执行。完整 DMG 与 Apple CMS 信任仍未验证；Ghidra 的 Objective-C analyzer 报错保留在日志中，不能声称获得完整 Objective-C 调用图。

| 函数及地址 | 直接观察 | 仍未建立的结论 |
| --- | --- | --- |
| `GetDisplayUpdateTime`，`0xddea4` | 按明确的 display ID 查找已有时间，缺失返回零 | 全局最早截止时间、公平性及完整队列排序 |
| `AddActiveDisplays`，`0xde147` | 遍历前采样一次时间，再为各设备调用下一次唤醒时间计算 | 状态字节的全部含义、实际刷新率和调度优先级 |
| `Begin`，`0x1b4b6b` | 要求事务尚未打开，否则断言 | 嵌套事务支持 |
| `Commit`，`0x1b4be5` | 处理排队几何、关闭事务、失效累计区域，在此调用点有条件调度一次，再释放队列 | 全进程每帧仅一次调度、所有回调与 GPU fence 的行为 |
| `CommitCoalescing`，`0x2046ff` | 追加 `0xff` 终止符，调用序列化包装器，将长度大于 `0x2000` 的布尔值传入提交 | 最新提交替换旧提交、队列深度及背压策略 |

这些结构支持按输出保留 deadline、合并同一批更新通知的工程方向。下面的自适应步长与 Rust 算法属于 Realand 的实现选择，没有证据表明 macOS 使用相同算法。旧文档中将 Work-Interval 导入、125 ms 调度上界、`std::set` 名称或单个 `-1.25` 常量推导为完整运行机制的断言已收紧，见[逆向记录](macos-compositor-reverse-engineering.md)。

## 本轮实现

### 帧预算更快应对连续迟到

`src/frame_clock.rs` 对连续、有效的迟到呈现反馈使用有界的 1、2、4 倍步长，按当前刷新间隔计算；每次增加量限制为四分之一帧，有效预算仍保留截止余量。及时反馈、无目标的新反馈及 VRR 切换重置连续计数。重复或过期时间戳不参与预算学习。正常负载沿用原来的保守衰减，避免一次昂贵帧长期固定提前渲染。

实际生产 `FrameClock` 在固定刷新网格模型中运行：CPU 用时为一帧的 10%，24 帧 GPU 尾部为 60%，之后恢复 8,192 帧轻负载。60/120/144 Hz 的错过刷新次数均由 10 降为 4，240 Hz 由 9 降为 4，360 Hz 由 6 降为 3；恢复后的预算与原算法一致。这是模型结果，不能换算成真实桌面掉帧率。22 项 FrameClock 测试通过；将旧算法放回同一测试器会触发新增回归失败。

### 损伤区域保持精确覆盖并减少分配

`src/render_helpers/damage_region.rs` 集中六处重复实现，供 GLES mesh/particles 与 Vulkan native 效果使用。八个以内的区域直接存放在 `SmallVec` 中；只合并完整共享边，不扩大到未清空的像素。先用 i64 裁剪输入坐标，随后在有效边界内处理 i32 几何。

旧实现边拆分边向前 `swap_remove`，可能跳过一个尚未处理的原片段，导致半透明像素重复混合。新实现倒序处理当前原片段。四矩形回归、256 组固定种子像素覆盖检查、极端坐标及超过内联容量的区域测试均通过。

CPU 微基准三次运行中位数：单区域 45→34 ns，分配 2→0；八个相邻区域 252→213 ns，绘制裁剪 8→1；100 个碎片区域 19.669→7.497 µs，分配 106→4。重叠案例由 179 增至 215 ns，同时消除分配并保证正确覆盖。高度碎片化的精确并集仍可能产生平方级工作。

### SHM 拷贝移除多余写入

`src/render_helpers/vulkan/shm.rs` 在校验 offset/stride/长度后，直接向预留字节存储拷贝完整行或 packed damage，全部初始化完毕后设置 Vec 长度。保留 Smithay 的受保护 raw copy、错误返回、缓存及 GPU 上传语义。SIGBUS 的受保护读取结果被丢弃，不上传受损快照。

3840×2400 的完整快照每次少写 36,864,000 字节。提取实际前后拷贝循环的 CPU 微基准为 12.377→8.277 ms；24 像素更新条为 18.696→9.532 µs。这些数字不包含 GPU 和呈现时间，运行时系统负载未隔离，不能承诺相同比例的桌面加速。

### 窗口成员维护避免反复全表查找

`src/protocols/foreign_toplevel.rs` 将每个已跟踪窗口各自遍历布局的方式改为小集合直接查找、大集合一次标记扫描。四个以内继续走直接路径，避免常见单窗口场景增加成本；更多窗口使用 HashMap 标记，保持关闭事件先于更新、焦点更新最后执行的原有顺序，不另建临时 surface 集合。

迭代范围覆盖最小化、屏幕外、无输出和交互移动窗口，不能替换成可见窗口集合。实际 Wayland fixture 验证卸载/重映射、最小化、无输出和脱离工作区的交互移动。无输出和交互移动状态均覆盖小集合与扫描分支；最小化、卸载/重映射回归覆盖扫描分支。测试检查窗口生命周期及协议状态；没有新增客户端 wire-event 次序测试。

实际 mapped Wayland 窗口的 debug 构建 CPU 微基准，九轮交替前后算法、每轮 256 次扫描，中位数为：8 窗口 7.089→4.068 µs，16 窗口 27.270→7.940 µs，128 窗口 1,249.991→50.036 µs。1/2/4 窗口仍使用原查找方式，分别增加约 9/20/42 ns 的条件与标记成本。计时不包含绘制与呈现，不能当作 release 桌面帧率。

### Dwindle 消除递归中的大型对象栈复制

完整默认线程栈测试暴露 `dwindle_many_windows_keep_session_serializable` 在插入时栈溢出，尚未进入序列化。树深度虽已限制为 32，每层仍按值传递大型 `Tile`；旧 debug 生产 `Mapped` 单态每层插入约 71,560 字节，删除约 283,944 字节。

`src/layout/dwindle.rs` 在入口将 Tile 装箱一次，递归传递 Box 并复用叶节点的分配；删除时递归返回原 Box，在外部边界解包一次。保持深度限制与线程栈大小，无每层新增分配。原有 96 窗口插入、保存、恢复、逐个删除回归保持原样并通过。

新 debug 二进制反汇编的 `Mapped` 插入递归每层栈预留为 1,000 字节，删除为 2,056 字节；原来分别为 71,560 与 283,944 字节。32 层删除递归本身从约 8.67 MiB 降至 64.25 KiB，这个计算不包含返回地址和其他被调用函数的栈帧，也不是 release 构建栈耗用测量。

## 验证与激活

默认配置核心库完整测试为 745 通过、0 失败、103 ignored。额外使用 `scripts/check-vulkan.sh` 在 Intel Iris Xe 与 NVIDIA RTX 2050 上启用 Khronos 与同步验证，每个节点 Rust harness 为 100 通过。Intel 有 1 项、NVIDIA 有 2 项可选 NV12 能力在测试内部明确跳过；这些不能计为已执行的像素覆盖。其余检查含 CPU 测试与自动设备选择测试，也不能全部计为所选显卡上的硬件案例。两块显卡所选设备上的必需像素、SHM、重叠 damage 和同步检查通过，无 VUID、Validation Error/Warning 或 SYNC-HAZARD。

当前桌面被动采样来自旧进程：3840×2400/60 Hz 下，历史近期 CPU 端渲染墙钟 P95 约 9.057 ms、呈现误差 P95 约一帧。30 秒采样里的慢路径为 Vulkan 渲染墙钟时间，包含调度等待，不能换算为 CPU 自用时间或 GPU 执行耗时。这只是现有问题的线索，采样期间有活动应用，不能当作隔离负载或新旧对照。

发布时使用用户目录的版本化二进制与原子启动链接，保留旧版本与安装记录。新程序需保存工作后退出并重新登录才能接管桌面。下一次实机验收应固定输出模式和工作负载，测量呈现误差、错过刷新、输入延迟与资源占用，覆盖滚动、窗口移动、概览、SHM 客户端、直接扫描切换及混合刷新输出。目前不宣称消除了全部卡顿或已达到 macOS 等效表现。
