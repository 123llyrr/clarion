本轮实现

realand-core 只依赖 smallvec，不持有 Smithay、Wayland 或 GPU 对象。桌面模型管理
稳定窗口/空间身份、焦点、最小化与交互状态。输出/工作区选择改由核心的稳定 ID
策略管理，原索引选择字段已删除；平台层保留客户端对象、协议事务与设备句柄。

浮动、滚动列、动态 BSP 布局使用同一纯布局策略接口。策略只产出几何结果，平台
层负责应用客户端尺寸约束与 Wayland configure。切换模式保留身份、归属与各模式
记录。滚动布局改用保留的缓冲区；五种参数组合的分配回归在预热后完成 1,000 次
脏布局、80,000 个结果单元而未发生堆分配。这是布局局部结果，不能推算整帧性能。

输出场景使用统一的不可变 pass 顺序和 renderer-specific SceneSnapshot。设备绘制
入口通过受限 FramePort 消费场景及协议反馈，无法取得完整桌面状态；平台协调器
负责场景准备、设备事件、协议反馈和调度。阴影、模糊、液态玻璃及现有 Shell 保留。

每个输出持有独立时钟与调度状态。动画按预计呈现时间取样，时钟投影不会改变
主线程的真实时间；打断、反向、重新指定目标承接位置和速度。窗口网格与 Genie
变形的真实状态推进和未来取样分开，避免多个输出和截图提前改变物理状态。
连续拖动输入按帧合并，离散边界保持顺序。显式同步、FIFO、提交时序、管线预热
及损伤处理继续保留。

截图、PNG/文件处理、SHM screencopy 读回及录屏光标像素转移采用受限异步任务。
主线程拥有核心状态；任务只持有像素、完成许可和必要的 GPU 资源寿命对象。
锁屏/场景 epoch 阻止旧内容在完成后发布，缓冲区在真实 GPU 完成前不会释放。
无 EGL fence 的 GLES 环境保留明确告警的同步兼容回退。

第二版修复了实际显示测试发现的 Vulkan 嵌套输出反转。原初始化和配置重载按
winit 名称强制套用 GLES 的 Flipped180 规则；现在使用实际选定后端的 framebuffer
origin。GLES 保留其既有约定，Native Vulkan 保留用户请求的正常变换。未修改 PNG
读回行序、通用 DMA-BUF 方向或通过测试图片翻转来掩盖问题。第一版候选拒绝安装，
失败截图、日志和诊断收据保留。

尚待物理会话验收

重新登录第二版后，以相同显示器、分辨率、缩放、窗口和操作场景连续拖动窗口、
切换桌面、开关概览，采集完整原始序列。固定 60 Hz 下目标：输出呈现之间主线程
CPU 工作 P95 不超过 4.1667 ms；持续活动的呈现间隔大于 25 ms 的比例低于 1%。
同时报告最大值、全部异常、缺样及版本/输出身份。多输出主线程时间保守重叠，
worker 时间另有范围；GPU 指标仅覆盖 native_output_command_buffer，不代表全部
GPU/KMS/WSI 工作。旧运行版本没有精确主线程 CPU 原始覆盖，不能作该口径的数值
前后对比。60 Hz 实机结果也不能证明物理 120 Hz 或更高刷新率表现。

跨屏与混合缩放、热插拔、锁屏、录屏、GPU 恢复等已有协议/离屏回归保留，但当前
真实会话完整场景矩阵和端到端输入延迟还需实际操作验收。重新启动合成器会结束
图形应用，必须先保存工作再切换会话。
