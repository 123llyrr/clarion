# macOS 动画与调度方案实施记录

2026-10-10。依据用户提供的《Wayland 合成器 macOS 极致流畅动画与调度设计方案》，
并使用用户指定的 [REA](https://github.com/morluto/rea) 再次检查本机提取的 Catalina
QuartzCore 和 SkyLight。本文区分二进制事实、Realand 的设计选择与仍需实机验证的工作。
函数地址、样本哈希、REA Evidence ID 和工具链信息见 [镜像证据复核](macos-rea-evidence.md)。

## 本轮实现

| 范围 | 实施结果 |
| --- | --- |
| 架构与帧时钟 | 保留现有原生合成器与 Flutter 外壳边界。每输出预测呈现时刻、冻结动画时钟、自适应 latch、渲染与晚醒预算、动画续帧和 VRR 空闲恢复已有实现。 |
| 弹簧 | 欠阻尼收敛改为直接计算位置和速度包络的对数截止期，包含非零初速度。临界和过阻尼继续使用有界搜索；所有截止期向上保留一纳秒，避免提前终止。 |
| 交互参数 | 窗口移动、缩放默认使用阻尼比 0.92、刚度 300、容差 0.001。这是方案建议的 Realand 调校，不是已恢复的苹果交互参数。显式 KDL 覆盖继续生效。 |
| 打开窗口 | 内置及新配置模板采用 255 ms 与 `macos-default` 曲线。保留已有四次方超椭圆 GPU 着色器；该几何来自 Denial，不是已验证的 macOS 开窗形状。 |
| Genie | Dock 一侧的网格行在进度 0.75 完成收口，其余行平滑延后至 1.0。纵向运动连续，消除原分段公式在 0.75 的形状跳变和中途停顿。保留原生网格、反向播放、目标重定向、最后 10% 淡出。450/300 ms 是项目设定。 |
| 动量交接 | 工作区和横向拖放释放保留当前附加布局动画的位置与速度，再叠加手势速度；已有普通触控板惯性传递继续使用。 |
| Vulkan 快照 | 原生调整大小快照采用 `freeze_native`。复制和后续采样在同一图形队列通过屏障排序；完成任务持有源缓冲区与 GPU 图像，避免主线程重复等待复制完成。 |

原生缓冲区所有权无法取得时仍同步完成，其他渲染器的冻结路径仍等待完成。
不能简单删除所有 fence 等待或把错误当作成功，否则客户端会过早重用仍在采样的存储。

## 方案中需要纠正的推断

- Catalina SkyLight 中 `_SLSCreateGenieWindowAnimation` 的函数体只有 11 字节，是返回桩。
  越过符号边界反汇编到的 Sheet 函数不能归到 Genie，因此这些材料尚不能证明
  0.75 是 Genie 原版阶段阈值，也不能证明 450/300 ms 是原版最小化时间。
- `_derive_anim_duration` 中的 0.255 位于带有 0.01、0.5 边界的数值搜索中。
  单独发现这个常量不能推出所有系统过渡都是 255 ms。当前 255 ms 明确作为项目设定。
- 函数名或“正在动画”的状态标志不足以证明 WindowServer 提升至最高实时优先级，
  更不足以推导适用于所有显示器的固定 2–4 ms 提交裕量。Realand 继续采用现有自适应预算。
- 方案附件列出的测试数量是附件陈述，不能代替当前源码的实际测试结果。

## 验证与生效

测试覆盖弹簧位置和速度的后续收敛、临界/过阻尼舍入、配置覆盖、移动反向动量、
Genie 阶段交界的世界坐标和速度连续性、网格边界与不折叠、拖放释放时位置和速度连续。
手势数学测试采样 60/120/144/240/360 Hz 及 0.5/1/2 倍动画速度；这不等于对应显示器实测。

GPU 验证需要真实 render node，检查排队复制和采样不等待 CPU、在途图像寿命、
最终像素与截图/录屏隐私分支，以及原始 DMA-BUF 重用和输出缩放。

## 尚未完成的验收

- 当前屏幕只提供 60 Hz，且不支持 VRR；120/144 Hz 与 VRR 功耗和切换仍需相应硬件验证。
- Linux VRR 与苹果 ProMotion 不是同一显示协议；静止时按损伤停绘不能称为面板自动切换刷新模式。
- GLES 快照的同步等待及 GPU 故障恢复还需要独立的缓冲区所有权改造，不能据此宣称所有停顿已消除。
- 仍需 macOS 实机逐帧录制与同尺寸并排测量，才能标定原版 Genie、开关窗形状和速度。
- 桌面、Dock、控制中心和系统偏好设置的其余差异见 [剩余工作](macos-remaining-work.md)。
