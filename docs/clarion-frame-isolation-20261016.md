# 布局投影、帧诊断与关闭缓冲事务（2026-10-16）

本阶段在独立桌面策略和外部场景资源所有者之上，继续替换生产绘制入口。
保留现有配置、Shell IPC、三种布局和原生 Vulkan 后端。

## 普通桌面与 Expo

布局适配层一次生成工作区的数值几何、可见性、窗口位置和有序来源；投影不接收 renderer。
`scene/workspace_composition.rs` 实际负责浮动/平铺、移动/普通四个通道的组合，
以及裁剪、缩放、位移、阴影、插入提示和 Expo 边框。所有通道复用同一几何计划。
普通 `MonitorScene` 不保留完整 Monitor；旧普通 Monitor 绘制主体删除，兼容入口转入同一实现。

Stage、Spread 和 Cube 仍有明确的专用 Monitor 适配分支，Tile 的内部效果仍通过窄来源能力绘制。
这些是下一阶段的迁移边界，不能把本阶段描述成所有布局类型已经完全不依赖绘制适配。
所有来源保持原 RenderTarget，截图和录屏不改用可见输出快照。

## CPU 调查与已替换工作

历史 r4 与 runtime-scene-r1 数据跨 boot，后台桌面版本不同，且没有记录当时的频率和温度。
重复采样确认同一个 r1 二进制在当前 boot 也有明显 P95 波动。
这不能单独证明历史增量来自资源注册表、异步分配或热降频。
主线程 CPU 指标保留完整原始样本，既不删除查询相邻帧，也不拿 redraw 墙钟替代 CPU 工作。

当前 boot 的独立用户态 CPU 采样发现，切桌时 `clip_edge` 与三角形裁剪组装合计约占 8% 样本。
网格现在先执行四边 outcode 的充分判断：完全位于损伤矩形内的三角形直接保留顶点和 UV，
同处某一外侧的三角形直接丢弃；跨边界及非有限输入继续使用原半平面插值路径。
一万组差分回归对照完整算法，已有损伤遮挡和 GPU 像素回归继续适用。

KMS 身份只在真正捕获延迟帧或延迟帧就绪后核对，常态帧不再为该身份读取三次输出锁。
锁态、epoch、格式、渲染器和显示几何变化仍使旧帧失效。

`frame-timings` 在主线程只冻结固定容量的原始环和标量；分位数排序、原始数组组装及输出排序
移至已有 owned-data worker。`TaskPermit` 在冻结之前取得四个共享槽之一，覆盖预留、排队、
执行及未消费结果；取消和失败按 RAII 归还。工作线程不持有桌面、协议或 GPU 对象。
原字段、序号、generation、累计最大值和覆盖计数保持不变，render-time 的兼容别名复用同一结果。
冻结仍需固定数据复制和少量字符串分配，诊断查询仍可能扰动采样。

## 关闭时的源所有权

关闭回退使用显式 `OwnedDmabufSource` 保存准确的 Smithay Buffer 附件，不能只凭 DMA-BUF FD
推断客户端不会复用内容。捕获和导入都校验原附件与 DMA-BUF 对象身份；提交时完成任务持有
实际采样的源，GPU 完成之前不会提前发送释放。
正常提交清除旧事务，渲染器重建只使设备图像失效，独立源附件仍可用于重新导入。

精确一次性快照的冷分配、缺少源附件的公共裸 DMA-BUF 导入，以及测试 headless 后端的显式
等待仍有兼容边界，不能由这些改动推断所有主线程 GPU 等待已经归零。
实际性能验收必须绑定本阶段最终源码、软件/GPU回归和新 release 二进制，旧采样不能代替新验收。
