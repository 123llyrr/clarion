# Dock 最小化效果

macOS 风格设置的「最小化窗口时使用」提供 **神奇效果** 和 **缩放效果**。
Material 仍使用独立配置。旧 macOS 外壳 JSON 没有 `minimize_effect` 时按
`genie` 解析，未知配置值也保持该默认值。设置只改变之后开始的最小化呈现，
不会清空仍可见图标的目标矩形，也不会重新启动正在播放的动画。

窗口由合成器真实最小化，保留映射、窗口 ID、工作区归属和后续客户端提交。
普通布局和输入不再命中该窗口；从 Dock 激活时恢复它，并使其真正获得焦点。
两种效果都采样真实客户端内容，沿用各自输出、截图、录屏的隐私遮挡规则。

## 呈现方式

神奇效果从 Dock 所在边缘开始，把窗口内容当作一张通过固定漏斗的薄片拉向
应用图标。底部、左侧和右侧 Dock 使用对应方向的形变；同一轴向变换也支持
顶部目标。方向显式来自 Dock 位置，不用窗口和图标之间最大的位移猜测，因此
位于对角线的图标不会造成收口方向错误。

主路径是逐像素逆映射片元着色器：侧轨使用 usagimaru/GenieWarpMesh 的 MIT
许可三次贝塞尔控制点（窗口到入口的 45% 与 65%），入口在进度 0.55 前形成，
后端在 0.38 后开始移动，内容持续从窗口中送入图标并从图标处采样返回。GLES
与原生 Vulkan 共享同一份 `genie.frag`，原生路径使用预编译 SPIR-V；离屏纹理
容量大于当前窗口时，`texture_scale` 只采样已使用的左上区域。窗口尺寸和输出
比例不会增加逐帧 CPU 工作量，侧轨在输出空间计算并保持纹理原始方向。

当着色器不可用或编译失败时，保留 Clarion 原有的 32×4 网格逐行收口作为
回退：最多 768 个三角形顶点，行始终有序且不回折；反向播放、目标重定向、
末尾淡出和隐私遮挡与主路径一致。该回退只在着色器路径不可用时启用。

缩放效果保持窗口原始比例，均匀缩小并移入图标中心；最终矩形等比适配图标
范围。它继续使用原有 GLES/Vulkan 网格路径，不经过漏斗着色器。

神奇效果使用 550 ms，与 niri-edge 的预设一致；最后按方向短淡出，最小化在
末尾 6%、从 Dock 恢复在末尾 4% 内平滑降到透明，避免收口薄片在图标处突然
消失。缩放效果保留 250 ms，不做额外淡出。阴影 padding、输出取整和恢复途中
的布局变化都不会重新计算时序分段。

中途恢复从当前进度继续反向播放，不从端点重新开始。布局在窗口最小化期间
变化时，恢复动画平滑交接到当前布局位置。

「减少动态」或者合成器关闭动画时，两种效果都立即完成真实状态转换。
无有效目标、输出移除、锁屏或窗口销毁也会结束呈现并清理动画及纹理缓存。
自动隐藏后没有可见图标、滚出屏幕的图标和尚未稳定的图标仍不提供目标。

## IPC 兼容

`SetMinimizeTarget` 的动作格式保留。目标对象增加两个可选字段：

| 字段 | 值 | 省略时 |
| --- | --- | --- |
| `edge` | `bottom`、`left`、`right`、`top` | `bottom` |
| `effect` | `genie`、`scale` | `genie` |

例如底部 Dock 的缩放效果目标：

```json
{"Action":{"SetMinimizeTarget":{"id":4,"target":{"output":"eDP-1","x":800,"y":700,"width":48,"height":48,"edge":"bottom","effect":"scale"},"reduce_motion":false}}}
```

旧客户端仍能注册默认神奇效果；旧合成器忽略目标新增字段，继续执行已有
底部神奇效果。更新磁盘上的合成器不会替换正在运行的进程，新方向和缩放
效果在下一次登录后生效。外壳串行登记目标和策略，迟到的旧 IPC 回复不能
吞掉较新的效果设置；连接更换时不会把旧窗口动作重放到新会话。

  `最小化窗口时使用：`、`神奇效果`、`缩放效果`；SHA-256
  `f65aeb77aed85696b6fd2f77ab4061006a4f69668a9e4d5de1dcb8e80b36de23`。
- `Dock.app/Contents/Resources/zh_CN.lproj/DockMenus.strings`：
  `GENIE_EFFECT`、`SCALE_EFFECT`；SHA-256
  `647a5ab0d83c034682b06ab0c8d6850a55e651986de8d8f7e96584d156eece5a`。

[Apple 官方 Dock 配置说明](https://support.apple.com/guide/deployment/dock-payload-settings-depef1fdf19/web)
同样列出左右底部位置以及 Genie/Scale 二选一。资源可确认选项名称和语义，
不能单独证明私有插值曲线、时间或完整 Dock 实现。

本次 Big Sur 11.7.2 / 20G1020 的完整 ARM64e Dock 静态分析确认：
正常 Genie 分支默认 0.5 秒，Scale 分支默认 0.25 秒；相关偏好和慢速分支
会改变实际时长。Genie 的横向形变与纵向移动分别采样半余弦，阶段交界由
源窗口、目标矩形和方向共同决定，而不是固定的 75%。纯数值层保留恢复
公式中的归一化进度 float32 量化，并使用原始指令离线样本核对。

这些阶段公式不能直接替代完整空间 warp。此前版本将恢复出的阶段与
`cross² + cross*(1-cross)*spatial` 近似组合，横向阶段提前结束时整窗会先
变为等宽细长矩形，而纵向移动尚未结束；这不是已恢复的 Apple 完整行为。
当前默认改为 niri-edge 的固定漏斗逆映射，并按项目需要移植到 Clarion 的
GLES/Vulkan 双后端；它仍是独立视觉实现，不宣称是 Apple warp 的一比一复刻。
纯数值层继续保存 Big Sur 阶段模型和离线指令样本，作为研究资料，不直接
驱动当前默认效果。

当前漏斗、反向速度交接、目标重定向、550 ms 时序和 32×4 网格回退均是
Clarion 的设计；Scale 保留等比缩放和 smoothstep，因为该分支的完整原始
时间函数未获确认。漏斗侧轨控制点来自 usagimaru/GenieWarpMesh（MIT），
分发时随 `src/render_helpers/shaders/genie.LICENSE` 保留原始许可声明。
静态数值与离线模拟验证不等同于 Big Sur 实机测量；实现变化仍需真实桌面
呈现反馈验收，不能只凭私有常量或单个 CPU 微基准断言整体更流畅。

历史 Catalina 核查发现 `_SLSCreateGenieWindowAnimation` 是 11 字节返回桩；
越过函数边界得到的后续 Sheet 常量不能当作 Genie 证据。原先的 0.75 收口
阈值属于 Clarion 自己的逐行设计，而不是 Apple 原始阶段比例。
独立最小化窗口缩略图、Downloads 叠放、最近应用区及其他完整 Dock 能力
是另外的功能，不由这两种动画自动具备。
