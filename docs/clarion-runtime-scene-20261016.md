# 运行时与场景资源迁移（2026-10-16）

本阶段替换保留图像的所有权和 GPU 就绪协调，保持现有桌面模型、三种布局、
配置、Shell IPC 和原生 Vulkan 路径。它不表示所有平台适配代码已成为 GPU 无关的纯算法。

## 所有权

`Clarion` 在桌面运行时旁持有一个 `SceneResources`。生产 `Layout`、`Workspace` 和
三种布局适配器仅持有可复制的弱 `SceneResourceAllocator`；`Tile`、`Monitor`、
`Mapped` 和关闭动画持有不可复制的注册句柄。句柄标识在移动、停放和布局切换时保持不变。
退出时先释放布局注册，再释放场景所有者。

场景注册表分别保留窗口、输出、已映射窗口的提交快照和关闭快照：

- 窗口：开窗、透明度、弹性、最小化和缩放缓存，以及解除映射前的快照。
- 输出：桌面立方体的离屏图像、冻结元素和概览/舞台文本纹理。
- 协议适配：应用新提交前捕获的 GLES/Vulkan 缩放图像。
- 关闭动画：显示、截屏和录屏各自的隐私快照、遮挡图像及 DMA-BUF。

布局中的开窗、缩放和透明度动画只保存轨迹与数值状态。渲染期间申请短期 lease，
使正在准备的操作可以安全完成；lease 不保存在布局字段中。注册删除先退出表的借用，
再析构资源，允许资源析构连带删除其他注册而不触发 `RefCell` 重入。
键在单个实例中单调递增且不重用，注册表之间不能访问彼此的条目。

正常生产构造必须显式传入外部场景分配能力。仅单元测试的便利构造器持有测试专用所有者；
视觉测试也在夹具中显式持有独立场景所有者，不另建生产执行路径。

## GPU 就绪和延迟呈现

无法导出或导入的生产者 fence 采用非阻塞检查：未就绪时不提交本次场景，保留上一帧并重试。
检查失败与等待中分开，设备错误不能伪装成永久等待，也不能伪装成完成。
即使渲染元素忽略某次 acquire 错误，帧结束仍拒绝提交该场景。

KMS 在需要等待完成时保留该次已准备的 swapchain slot、场景状态和呈现反馈。
GPU 未完成前既不复用 slot，也不发送呈现反馈。反馈在原场景渲染时捕获，避免把
等待期间到达的新客户端提交算作旧画面已呈现。旧帧提交后再请求一次最新场景重绘，
保留等待期间合并的最终输入和动画结束状态。

DPMS、VT 复位、显示模式和渲染器重建使帧 epoch 失效；就绪的旧 epoch 帧丢弃后重新绘制。
失败 fence 的协议反馈立即丢弃，GPU slot 继续隔离持有，不能把失败当作可回收完成。
隔离数量有限，并进入现有 GPU 恢复流程。嵌套输出采用对应的缓冲、反馈和补绘约束。

同步文件导出不是保持缓冲寿命的前提。无同步文件能力时可在后台等待 Vulkan fence，
设备端等就绪再提交；采样到的 Wayland 缓冲及图像由完成任务保留。

## 冷离屏分配

可重试的 TTY、嵌套和无头显示帧显式进入 `AsyncOffscreenScope`。持久动画缓存通过
`create_offscreen_capacity` 请求容量，后台 worker 采用 256 像素容量桶，允许复用
同格式的较大 ready 图像；返回值保留真实纹理尺寸，geo 定义可见区域，damage tracker
使用实际容量。缓存 miss 返回 `OffscreenAllocation` 忙状态，场景标记为延迟，继续显示
旧帧并等待完成唤醒。嵌套输出通过独立的 `create_exact_frame_target` 保持宿主 extent 精确。

普通 `Offscreen::create_buffer` 保持精确尺寸的同步兼容契约，即使位于显示帧 scope 内也
不会隐式变成异步。一次性 commit/unmap/close 和 `OnceCell` 捕获不会因首次分配忙而永久
漏掉快照。该边界也意味着本阶段尚未移除所有显示帧的冷分配。

每个渲染器最多保留一个 pending 和两个 ready，provider 总共最多两项请求/结果；
准备阶段按真实 allocation bytes 限制为 256 MiB，回收缓存同时限制为八张及 64 MiB。
这些是准备和回收预算，不是全部活动图像的总显存上限。暂时 OOM/预算错误采用
250 ms 到 4 s 的退避后允许重试，设备丢失和不支持格式仍按真正错误处理。
`NativeCompatibilityWork` 分别累计兼容冷分配与无外部存储所有者的同步帧，用于硬件回归；
它不是已经公开的 Shell IPC 性能字段。

## 动画和惰性快照的重试

资源忙与真正渲染错误分别处理。弹性拖动、最小化、开窗、透明度、缩放和桌面立方体
遇到可重试的 GPU 背压时保留数值动画及资源注册，由场景延迟机制继续；不会因首次缓存
尚未准备好就主动结束动画。真正错误继续执行各自已有的安全降级。

惰性 `RenderSnapshot` 的三条隐私缓存也不把背压记录成永久失败：等待中保持所选
`OnceCell` 未初始化，成功后缓存图像，真正错误仍缓存 `None`。截屏/录屏不会改用输出的
无遮挡快照。已经应用新客户端提交前的必要冻结仍需独立事务语义，不由该惰性缓存替代。

## 兼容边界和下一步

原始 `ImportDma` 导入无法总是找到可保留的客户端存储所有者；这条安全边界仍需同步完成。
删除等待会让调用方在 GPU 采样结束前复用或释放原始存储。后续必须先引入显式外部存储
所有权或可重试的独立复制事务，才能替换这条路径。

布局适配器仍有 Smithay 几何、协议对象和渲染入口；本阶段将其保留图像移出，尚未把所有
绘制函数改为对纯值场景图的消费。纯数值策略和生产适配器的责任仍应分别审计。
冷启动、协议提交前的一次性快照和兼容 GLES 路径也不能由正常帧的异步改动推断为无阻塞。
实机流畅度必须绑定新构建重新采样，不能沿用旧版本的帧时间验收。

## 检查

模块守卫拒绝布局字段重新持有强场景注册表或 GPU 图像。它识别真实的 `#[cfg(test)]`
外部模块，同文件测试模块后的生产代码仍检查。Nix 源码闭包测试覆盖所有 workspace crate、
本地依赖与嵌入资源，避免发布时遗漏 motion/timing/scene。

```sh
python3 scripts/check_module_boundaries.py
PYTHONPATH=scripts python3 -m unittest discover -s scripts -p 'test_*.py'
cargo test --workspace --exclude clarion-visual-tests --locked --offline
cargo clippy --workspace --all-targets --locked --offline -- -D warnings
```

GPU 忽略测试需分别选择真实 Intel/NVIDIA 节点和 Vulkan 验证层；未执行或被忽略的测试
不是通过。实际拖动、切换桌面和概览的帧时间、异常样本与干净退出应记录在该构建的独立回执中。
